# analysis/

Paper RQ1 / RQ2 reproduction tables, plotting code, and the shared utility
library that walks the unified data tree.

```
analysis/
├── skillmutator_utils/   # shared library (paths, refusal classification, ...)
├── rq1/scripts/
│   ├── build_tab1_cross_matrix.py        # Table 1
│   └── build_tab2_refusal_summary.py     # Table 2
└── rq2/scripts/
    ├── build_tab_iter_trajectory.py
    ├── build_tab_iter_trajectory_per_oracle.py
    ├── build_tab_select_vs_noselect.py
    └── plot_iter_trajectory.py
```

## Configuration

Every script reads the unified data tree at `${SKILLMUTATOR_DATA_ROOT}` (set
via env var, defaults to `./data/skillmutator-data`).

```
${SKILLMUTATOR_DATA_ROOT}/
└── <oracle>/<mode>/<skill>/<cat_folder>/iter_K/
    ├── meta.json                {oracle, mode, skill, ..., classification}
    ├── injected_content.md      attack ground truth (<= 1500 chars/file)
    ├── ss/{report.md, verdict.json}        SS strict count-delta criterion
    ├── snyk/{report.md, verdict.json}      Snyk lenient identity-delta
    └── llm/<scanner>/{scan.md, judge_v2.json, verdict.json}
                                 scanner output + GPT-5.4 v2 judge
```

To populate this tree from scratch, see [docs/REPRODUCE.md](../docs/REPRODUCE.md)
in the repo root. The tree itself is **not** distributed with the repo; it is
generated by running the SkillMutator pipeline + each of the five scanners
against your skill collection.

## Running

```bash
export SKILLMUTATOR_DATA_ROOT=/path/to/your/Skillmutator-data
python analysis/rq1/scripts/build_tab1_cross_matrix.py
```

Each script writes its outputs to its own adjacent `outputs/` directory
(created at runtime).
